PHẦN VI · UNITY NETCODE FOR GAMEOBJECTS

Unity Relay & Lobby Services

Các chương 32–35 đã trang bị đầy đủ khối xây dựng gameplay của NGO (Netcode for GameObjects), nhưng vẫn còn một câu hỏi hạ tầng chưa trả lời: hai người chơi ở hai mạng gia đình khác nhau, phía sau hai router NAT khác nhau, làm sao tìm thấy nhau và kết nối được với nhau qua Internet, nếu không ai tự host một server có địa chỉ IP công khai? Unity Gaming Services (UGS — bộ dịch vụ cloud chính thức do Unity Technologies vận hành, đi kèm và tích hợp sẵn với NGO) trả lời câu hỏi này bằng hai dịch vụ bổ trợ nhau: Unity Relay giải quyết bài toán kết nối xuyên NAT, và Unity Lobby giải quyết bài toán tìm phòng chơi. Chương này trình bày cả hai và cách kết hợp chúng thành một quy trình "tạo phòng — vào phòng — kết nối" hoàn chỉnh.

Vấn đề NAT Traversal — vì sao cần Relay

NAT (Network Address Translation — cơ chế router "dịch" nhiều địa chỉ IP nội bộ trong mạng gia đình/công ty thành một địa chỉ IP công khai duy nhất khi ra Internet) khiến hai máy tính đều nằm sau NAT thường không thể kết nối trực tiếp (P2P — Peer-to-Peer) với nhau mà không có một bên thứ ba hỗ trợ "dẫn đường" ban đầu. Đây chính là lý do PUN (chương 20) và Fusion (chương 26) đều dựa vào hạ tầng máy chủ trung chuyển của Photon Cloud thay vì bắt người chơi tự mở cổng router (port forwarding) — một thao tác kỹ thuật phức tạp, không thực tế với người chơi thông thường. Unity Relay là câu trả lời tương đương của hệ sinh thái Unity/NGO cho đúng vấn đề này.

C# Unity Relay — Allocation & Join Code

Ý nghĩa: Unity Relay là dịch vụ máy chủ trung chuyển (relay server) do Unity vận hành trên hạ tầng cloud toàn cầu — mọi gói tin giữa các người chơi trong cùng một phiên đều đi qua máy chủ Relay này thay vì cố gắng kết nối trực tiếp P2P, loại bỏ hoàn toàn nhu cầu bất kỳ người chơi nào phải tự host server hay cấu hình router. Quy trình gồm hai bước cốt lõi:

BướcÝ nghĩa
1. Tạo AllocationMột Client (thường là người chơi giữ vai trò Host) gọi API tạo một "Allocation" — một chỗ dành riêng trên hạ tầng Relay, cấp phát vùng đệm và tài nguyên cho đúng phiên chơi này, kèm giới hạn số kết nối tối đa cho phép.
2. Lấy Join CodeTừ Allocation vừa tạo, Host lấy về một "Join Code" — một chuỗi ký tự ngắn gọn (thường chỉ 6 ký tự) rất dễ đọc, dễ gõ tay hoặc dễ chia sẻ qua tin nhắn/voice chat, đại diện cho đúng phiên Relay vừa tạo.
3. Client khác Join bằng Join CodeNgười chơi khác chỉ cần nhập đúng Join Code này, gọi API tương ứng để "gia nhập" đúng Allocation đó — từ đây cả hai bên đều được kết nối vào cùng một phiên thông qua Relay, không ai cần biết địa chỉ IP thật của người kia.
C# RelaySetup.cs — khởi tạo dịch vụ và tạo Allocation phía Host
using System.Threading.Tasks;
using Unity.Services.Authentication;
using Unity.Services.Core;
using Unity.Services.Relay;
using Unity.Services.Relay.Models;
using Unity.Netcode;
using Unity.Netcode.Transports.UTP;
using UnityEngine;

public class RelaySetup : MonoBehaviour
{
    // Buoc 0 - bat buoc: khoi tao UGS va dang nhap (co the dang nhap an danh,
    // khong can tai khoan nguoi choi that su, chi de dinh danh phien lam viec
    // voi cac dich vu Relay/Lobby)
    async Task InitServicesAsync()
    {
        await UnityServices.InitializeAsync();
        if (!AuthenticationService.Instance.IsSignedIn)
        {
            await AuthenticationService.Instance.SignInAnonymouslyAsync();
        }
    }

    // Phia Host: tao Allocation va lay Join Code de chia se cho nguoi choi khac
    public async Task<string> CreateRelayAsHostAsync(int maxConnections)
    {
        await InitServicesAsync();

        // maxConnections KHONG tinh Host - la so luong Client con lai duoc phep vao
        Allocation allocation = await RelayService.Instance.CreateAllocationAsync(maxConnections);
        string joinCode = await RelayService.Instance.GetJoinCodeAsync(allocation.AllocationId);

        // Gan thong tin Allocation vao UnityTransport cua NetworkManager (chuong 32)
        var transport = NetworkManager.Singleton.GetComponent<UnityTransport>();
        transport.SetRelayServerData(new RelayServerData(allocation, "dtls"));

        NetworkManager.Singleton.StartHost();
        return joinCode; // hien thi/chia se ma nay cho nguoi choi khac
    }

    // Phia Client: dung Join Code nguoi choi kia gui cho de vao cung phien
    public async Task JoinRelayAsClientAsync(string joinCode)
    {
        await InitServicesAsync();

        JoinAllocation joinAllocation = await RelayService.Instance.JoinAllocationAsync(joinCode);

        var transport = NetworkManager.Singleton.GetComponent<UnityTransport>();
        transport.SetRelayServerData(new RelayServerData(joinAllocation, "dtls"));

        NetworkManager.Singleton.StartClient();
    }
}
Lưu ý về phiên bản API: Package Relay/Transport của Unity cập nhật khá thường xuyên, tên hàm dựng RelayServerData hay các hàm tiện ích chuyển đổi có thể thay đổi nhẹ giữa các phiên bản — luôn đối chiếu tài liệu chính thức mới nhất khi triển khai thật, đoạn code trên minh hoạ đúng luồng khái niệm chứ không cam kết khớp 100% mọi phiên bản package.

Unity Lobby — danh sách phòng chờ

C# Unity Lobby

Ý nghĩa: Trong khi Relay chỉ lo phần "truyền dữ liệu qua NAT", Unity Lobby là dịch vụ quản lý danh sách phòng chờ trước khi trận đấu thực sự bắt đầu — vai trò tương đương khái niệm Lobby/Room mà PUN đã cung cấp (chương 21), nhưng ở đây là một dịch vụ độc lập, tách rời khỏi việc truyền dữ liệu gameplay thời gian thực. Lobby cho phép:

Chức năngÝ nghĩa
Tạo LobbyHost tạo một phòng chờ mới, đặt tên, giới hạn số người chơi tối đa, chọn công khai hay riêng tư.
Liệt kê Lobby công khaiClient truy vấn danh sách các Lobby công khai đang mở, hiển thị cho người chơi chọn phòng muốn vào — tương tự màn hình danh sách phòng của PUN.
Join theo mã / tự tìm phòng phù hợpCó thể join trực tiếp bằng một mã phòng (Lobby Code) do Host chia sẻ, hoặc để hệ thống tự tìm một phòng còn trống phù hợp theo bộ lọc tuỳ chỉnh (ví dụ cùng chế độ chơi, cùng khu vực máy chủ).
Custom Data (dữ liệu tuỳ chỉnh)Lưu thêm dữ liệu dạng khoá-giá trị (key-value) gắn trên chính Lobby (ví dụ tên bản đồ đã chọn, chế độ chơi) hoặc gắn trên từng người chơi trong Lobby (ví dụ đội đã chọn, trạng thái sẵn sàng) — mọi thành viên trong Lobby đều đọc được dữ liệu này, tương tự khái niệm Custom Properties của phòng PUN (chương 24).
C# LobbySetup.cs — tạo Lobby, đính kèm Join Code của Relay
using System.Collections.Generic;
using System.Threading.Tasks;
using Unity.Services.Lobbies;
using Unity.Services.Lobbies.Models;
using UnityEngine;

public class LobbySetup : MonoBehaviour
{
    Lobby currentLobby;

    // Host: tao Lobby va luu Join Code cua Relay vao Custom Data cua chinh Lobby do
    public async Task CreateLobbyWithRelayAsync(string lobbyName, int maxPlayers, string relayJoinCode)
    {
        var options = new CreateLobbyOptions
        {
            IsPrivate = false,
            Data = new Dictionary<string, DataObject>
            {
                // Visibility.Public: moi thanh vien Lobby deu doc duoc gia tri nay
                { "relayJoinCode", new DataObject(DataObject.VisibilityOptions.Public, relayJoinCode) }
            }
        };

        currentLobby = await LobbyService.Instance.CreateLobbyAsync(lobbyName, maxPlayers, options);

        // Lobby se tu dong bi xoa neu khong "heartbeat" dinh ky (mac dinh khoang 30 giay)
        InvokeRepeating(nameof(SendHeartbeat), 15f, 15f);
    }

    async void SendHeartbeat()
    {
        if (currentLobby != null)
        {
            await LobbyService.Instance.SendHeartbeatPingAsync(currentLobby.Id);
        }
    }

    // Client: liet ke Lobby cong khai dang mo
    public async Task<List<Lobby>> ListPublicLobbiesAsync()
    {
        QueryResponse response = await LobbyService.Instance.QueryLobbiesAsync();
        return response.Results;
    }

    // Client: vao Lobby bang ma phong, sau do doc relayJoinCode de tu ket noi Relay
    public async Task<string> JoinLobbyByCodeAsync(string lobbyCode)
    {
        Lobby joinedLobby = await LobbyService.Instance.JoinLobbyByCodeAsync(lobbyCode);
        return joinedLobby.Data["relayJoinCode"].Value; // dung gia tri nay goi JoinRelayAsClientAsync()
    }
}
Lưu ý về Heartbeat: Một Lobby đã tạo sẽ tự động bị xoá khỏi hệ thống nếu Host không định kỳ gọi SendHeartbeatPingAsync() (mặc định khoảng 30 giây không heartbeat sẽ bị coi là phòng "chết"/bỏ hoang) — quên cài đặt vòng lặp heartbeat là lỗi rất hay gặp khiến Lobby vừa tạo xong đã biến mất khỏi danh sách sau một khoảng thời gian ngắn, dù Host vẫn đang chạy game bình thường.

Khác biệt kiến trúc đáng chú ý nhất: PUN gộp chung vai trò "phòng chờ" và "kênh truyền dữ liệu" vào cùng một khái niệm Room, còn hệ sinh thái Unity tách bạch hai dịch vụ này — Lobby chỉ quản lý metadata phòng chờ, Relay chỉ lo việc truyền gói tin — đòi hỏi lập trình viên tự kết hợp cả hai (như minh hoạ ở mục tiếp theo), đổi lại có thể dùng Lobby độc lập cho những mục đích không cần gameplay thời gian thực (ví dụ một hệ thống ghép đội trước khi vào game).

Đọc sơ đồ: Bốn bước cốt lõi luôn theo đúng thứ tự: (1) Host tạo Relay Allocation trước để có Join Code, (2) Host tạo Lobby và nhét Join Code đó vào Custom Data của Lobby để chia sẻ gián tiếp, (3) Client tìm/join đúng Lobby rồi đọc lại Join Code, (4) Client dùng Join Code đó tự join vào cùng phiên Relay. Lobby ở đây đóng vai trò "tấm biển chỉ đường" giúp Client tìm ra đúng Join Code của Relay, chứ bản thân Lobby không tham gia truyền bất kỳ gói tin gameplay nào.

Tổng kết chương

Unity Relay giải quyết bài toán NAT Traversal bằng một máy chủ trung chuyển do Unity vận hành — không ai phải tự host server hay mở cổng router, đổi lấy việc mọi gói tin đều đi qua một chặng trung gian (tương tự triết lý Photon Cloud Relay ở chương 20). Unity Lobby giải quyết bài toán tìm phòng bằng một dịch vụ quản lý danh sách phòng chờ tách biệt, có thể đính kèm Custom Data tuỳ ý — kết hợp cả hai cho ra đúng quy trình "tạo phòng, chia sẻ mã, vào phòng, tự động kết nối" mà hầu hết game multiplayer indie/casual cần tới. Chương 37 sẽ ghép toàn bộ Phần VI lại thành một ví dụ hoàn chỉnh: từ thiết lập NetworkManager dùng Relay Transport, tạo/join Lobby, cho tới spawn Player có đầy đủ NetworkObject, NetworkTransform, NetworkVariable máu, và xử lý tấn công bằng ServerRpc/ClientRpc.
