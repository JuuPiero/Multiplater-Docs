PHẦN VII · FISHNET

Ví dụ: thiết lập FishNet cơ bản

Chương cuối cùng của Phần VII ghép toàn bộ kiến thức từ chương 38 đến 41 thành một quy trình thiết lập FishNet hoàn chỉnh trong một project Unity: cài đặt package, cấu hình NetworkManager, tạo Player Prefab, rồi viết một PlayerController đầy đủ kết hợp [SyncVar] (chương 39), [ServerRpc] (chương 40) và Prediction v2 cơ bản (chương 41). Kết thúc chương là bảng tổng kết toàn Phần VII, giúp quyết định khi nào nên chọn FishNet thay vì NGO hoặc Fusion cho một dự án thực tế.

1. Cài đặt FishNet vào project Unity

FishNet là mã nguồn mở, miễn phí, có hai cách cài đặt phổ biến:

Cách cài đặtQuy trình
Asset Store (khuyến nghị cho người mới)Mở Unity Asset Store, tìm "FishNet: Networking Evolved", nhấn Add to My Assets rồi import trực tiếp qua Package Manager > My Assets. Đây là bản ổn định, cập nhật định kỳ.
Git URL qua Package ManagerWindow > Package Manager > nút + > "Install package from git URL..." > dán địa chỉ repository GitHub chính thức của FishNet. Phù hợp khi cần bản mới nhất trực tiếp từ nhánh phát triển, hoặc khi muốn ghim đúng một commit/tag cụ thể trong manifest.json.
Ghi chú: Vì FishNet mã nguồn mở, một lựa chọn thứ ba cũng khả dụng: clone trực tiếp repository về máy và copy thư mục FishNet vào Assets/ hoặc Packages/ của project — hữu ích khi cần sửa đổi trực tiếp mã nguồn framework cho nhu cầu tùy biến sâu, đúng như đã nhắc ở bảng so sánh cuối chương 41.

2. Thiết lập NetworkManager

Sau khi cài đặt, tạo một GameObject trống trong scene khởi động (thường đặt tên NetworkManager) và gắn component NetworkManager riêng của FishNet — component này khác hoàn toàn với NetworkManager của NGO (chương 32) dù trùng tên, không thể dùng lẫn giữa hai framework.

NetworkManager (FishNet)

Ý nghĩa: Component trung tâm quản lý toàn bộ vòng đời networking của ứng dụng: khởi động Server, khởi động Client, quản lý danh sách NetworkObject đã spawn, điều phối Transport (tầng vận chuyển gói tin bên dưới, ví dụ Tugboat — transport TCP/UDP mặc định đi kèm FishNet, hoặc các transport thay thế như LiteNetLib).

Thành phần con cần gắn kèmVai trò
Transport (ví dụ Tugboat)Tầng vận chuyển thật sự gửi/nhận gói tin qua mạng — FishNet tách rời phần logic networking khỏi tầng transport cụ thể, cho phép đổi transport khác nhau (ví dụ chuyển sang Steamworks transport cho game phát hành qua Steam) mà không phải viết lại logic gameplay.
ServerManager, ClientManagerHai sub-module tự động đi kèm NetworkManager, quản lý riêng vòng đời phía Server và phía Client (bắt đầu/kết thúc kết nối, danh sách connection đang hoạt động...).
SceneManager (FishNet)Quản lý việc đồng bộ scene giữa Server và các Client — đảm bảo Client load đúng scene tương ứng trước khi nhận spawn object.

Khi nào dùng: Bắt buộc phải có đúng một NetworkManager tồn tại trong scene trước khi có thể gọi bất kỳ API networking nào của FishNet — tương tự vai trò nền tảng của NetworkManager ở cả NGO (chương 32) lẫn khái niệm tương đương trong Fusion (NetworkRunner, chương 26).

3. Tạo Player Prefab

Quy trình tạo một prefab nhân vật sẵn sàng cho networking gồm ba bước, đúng cấu trúc đã học ở chương 39 (mục 1):

  1. Tạo GameObject nhân vật bình thường (model, collider, các component gameplay không liên quan mạng).
  2. Gắn component NetworkObject — đánh dấu object này được FishNet quản lý vòng đời (spawn/despawn) qua mạng.
  3. Gắn script kế thừa NetworkBehaviour (ví dụ PlayerController sẽ viết ở mục 4) chứa toàn bộ logic [SyncVar]/RPC/Prediction.

Sau khi hoàn tất, kéo GameObject này thành một Prefab, rồi gán vào ô Spawnable Prefabs trong cấu hình của NetworkManager (hoặc PlayerSpawner nếu dùng component hỗ trợ spawn tự động đi kèm FishNet) — đây là bước bắt buộc để FishNet biết prefab nào cần dùng khi một Client kết nối và cần được cấp một nhân vật.

4. Ví dụ code hoàn chỉnh: PlayerController

Script dưới đây ghép cả ba mảng kiến thức của Phần VII: [SyncVar] cho máu (Health, chương 39), [ServerRpc] xử lý input di chuyển (chương 40), và một khối Prediction v2 cơ bản (chương 41) để di chuyển mượt mà không chờ phản hồi Server.

C# PlayerController.cs
using FishNet.Object;
using FishNet.Object.Prediction;
using FishNet.Connection;
using UnityEngine;

public class PlayerController : NetworkBehaviour
{
    [Header("Gameplay")]
    [SyncVar(OnChange = nameof(OnHealthChanged))]
    private int health = 100;

    [Header("Di chuyen")]
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private UnityEngine.UI.Text healthText;

    // ----- Cau truc du lieu cho Prediction v2 (xem chi tiet chuong 41) -----
    public struct MoveInputData : IReplicateData
    {
        public float Horizontal;
        public float Vertical;
        private uint _tick;
        public void Dispose() { }
        public uint GetTick() => _tick;
        public void SetTick(uint value) => _tick = value;
    }

    public struct MoveReconcileData : IReconcileData
    {
        public Vector3 Position;
        private uint _tick;
        public void Dispose() { }
        public uint GetTick() => _tick;
        public void SetTick(uint value) => _tick = value;
    }

    public override void OnStartClient()
    {
        base.OnStartClient();
        RefreshHealthUi(health);
    }

    private void OnHealthChanged(int oldValue, int newValue, bool asServer)
    {
        RefreshHealthUi(newValue);
    }

    private void RefreshHealthUi(int value)
    {
        if (healthText != null)
            healthText.text = $"HP: {value}/100";
    }

    // Duoc goi tu vong lap tick cua FishNet (dang ky qua TimeManager.OnTick trong OnStartNetwork,
    // rut gon o day de tap trung vao phan logic Replicate/Reconcile cot loi)
    private void RunInputs(MoveInputData input)
    {
        // Ham nay PHAI deterministic: chi dung dung du lieu trong 'input',
        // khong doc Time.time, khong goi Random.Range() khong seed co dinh
        Vector3 move = new Vector3(input.Horizontal, 0f, input.Vertical) * moveSpeed * (float)TimeManager.TickDelta;
        transform.position += move;
    }

    // FishNet tu dong goi ham nay khi can rollback ve dung trang thai Server gui
    private void OnReconcile(MoveReconcileData data)
    {
        transform.position = data.Position;
    }

    // ServerRpc rieng cho hanh dong roi rac, khong lien quan Prediction:
    // vi du nguoi choi bam nut "hoi mau" tai mot tram y te trong map
    [ServerRpc]
    private void ServerRequestHeal(int amount, NetworkConnection requester = null)
    {
        if (!IsServerInitialized) return;
        health = Mathf.Min(100, health + amount);
    }

    // Ham cong khai de UI/Input System goi khi nguoi choi bam nut hoi mau
    public void RequestHeal(int amount)
    {
        if (IsOwner)
            ServerRequestHeal(amount);
    }
}
Lưu ý: Ví dụ trên rút gọn phần đăng ký callback tick (TimeManager.OnTick) và việc gọi RunInputs()/OnReconcile() qua API PredictionManager đầy đủ của FishNet để tập trung vào cấu trúc dữ liệu và nguyên tắc deterministic — khi triển khai thực tế, cần tham khảo đúng phiên bản FishNet đang dùng (API Prediction v2 có thể có khác biệt nhỏ giữa các bản phát hành) để đăng ký đúng các hàm Replicate/Reconcile theo signature framework yêu cầu.

5. Kiểm thử multiplayer cục bộ

Trước khi build ra nhiều máy thật để kiểm thử, cách nhanh nhất để xác nhận thiết lập ở trên hoạt động đúng là chạy nhiều tiến trình game trên cùng một máy phát triển:

Cách kiểm thửQuy trình
Host + một Build riêngTrong Unity Editor, gọi NetworkManager.ServerManager.StartConnection() rồi NetworkManager.ClientManager.StartConnection() để chạy vai trò Host (Server + Client cùng lúc, khái niệm đã học ở chương 27/32); đồng thời chạy thêm một bản Build (File > Build Settings) riêng biệt trên cùng máy, kết nối vào 127.0.0.1 (địa chỉ loopback, đã học ở chương 9) với vai trò Client thuần.
Nhiều instance Editor song songDùng công cụ nhân bản project (ví dụ ParrelSync, một tiện ích mã nguồn mở phổ biến trong cộng đồng Unity) để mở đồng thời hai cửa sổ Unity Editor trỏ chung một project mà không xung đột — mỗi cửa sổ đóng vai trò một Client riêng, tiện lợi khi cần debug qua breakpoint ở cả hai phía cùng lúc.
Giả lập độ trễ/mất góiFishNet cho phép gắn thêm một lớp giả lập điều kiện mạng xấu (latency simulation) phía trên Transport khi build ở chế độ Development — hữu ích để chủ động kiểm tra xem Prediction v2 (chương 41) có phản ứng đúng khi ping cao hoặc mất gói input, thay vì chỉ kiểm thử trong điều kiện mạng LAN lý tưởng.
Ghi chú: Khi kiểm thử bằng nhiều instance trên cùng máy, luôn dùng cổng (port) khác nhau nếu chạy nhiều listening server cùng lúc — nếu chỉ cần một Server duy nhất (mô hình phổ biến nhất khi kiểm thử: một Host + nhiều Client thuần), chỉ cần đúng một tiến trình gọi StartConnection() phía Server.

7. Tổng kết Phần VII: khi nào chọn FishNet?

Sau năm chương (38–42) đi từ tổng quan kiến trúc, đến SyncVar/SyncList, ba loại RPC, Prediction v2, và cuối cùng là ví dụ thiết lập hoàn chỉnh này, đây là bảng quyết định nhanh giữa FishNet và hai middleware Unity đã học trước đó — NGO (Phần VI) và Fusion (Phần V):

Tiêu chí lựa chọnChọn FishNet khi...So với NGOSo với Fusion
Chi phíMuốn miễn phí hoàn toàn, không giới hạn CCUNGO cũng miễn phí (do Unity phát hành), tương đương ở tiêu chí nàyFusion tính phí theo CCU vượt ngưỡng — FishNet có lợi thế rõ rệt
Prediction/RollbackCần cơ chế Prediction v2 mạnh, đóng gói sẵn rollback + resimulate (chương 41)NGO không có Prediction tích hợp sẵn ở tầng framework, phải tự xây hoặc dùng thư viện ngoàiFusion có Prediction built-in tương đương, nhưng đóng mã nguồn và trả phí
Tối ưu băng thôngCần Observer System lọc theo Interest Management tự động (chương 40), SyncList theo dõi delta từng phần tử (chương 39)NGO gửi [ClientRpc] mặc định cho mọi client, phải tự lọc thủ côngFusion cũng có Area of Interest (AOI) riêng, tương đối mạnh nhưng cấu hình khác biệt
Mã nguồn mở / tùy biến sâuCần đọc/sửa trực tiếp bên trong cơ chế networking cho nhu cầu đặc thùNGO mã nguồn mở (Unity công bố trên GitHub) — cũng tùy biến đượcFusion đóng mã nguồn hoàn toàn — FishNet có lợi thế rõ rệt
Hạ tầng cloud đi kèmSẵn sàng tự vận hành server/transport riêngNGO tích hợp tốt với Unity Relay/Lobby (chương 36)Fusion tích hợp Photon Cloud sẵn có, ít việc vận hành hạ tầng hơn
Độ trưởng thành cộng đồngChấp nhận cộng đồng mã nguồn mở, tài liệu không chính thức hóa như sản phẩm thương mạiNGO do chính Unity duy trì, tài liệu chính thức đầy đủFusion do Exit Games/Photon duy trì với hỗ trợ thương mại
