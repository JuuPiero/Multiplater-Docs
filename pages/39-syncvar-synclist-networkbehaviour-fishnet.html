PHẦN VII · FISHNET

SyncVar, SyncList & NetworkBehaviour trong FishNet

Chương 38 đã giới thiệu tổng quan FishNet và kiến trúc Client-Server Authoritative của nó. Chương này đi vào ba viên gạch nền tảng đầu tiên mà bất kỳ script gameplay networked nào của FishNet cũng cần: class cơ sở NetworkBehaviour — nơi mọi thứ bắt đầu; attribute [SyncVar] — cách đơn giản nhất để một field tự động đồng bộ giá trị từ Server xuống Client; và SyncList/SyncDictionary — phiên bản đồng bộ tự động của các cấu trúc dữ liệu tập hợp quen thuộc. Ba khái niệm này đã có "họ hàng" tương đương ở Fusion (chương 28) và NGO (chương 33), nên phần lớn thời gian của chương sẽ dành để đối chiếu điểm giống — khác, giúp việc học không phải bắt đầu lại từ số 0.

1. NetworkBehaviour — class nền tảng của FishNet

NetworkBehaviour là class cơ sở (base class) mà mọi script cần tới networking trong FishNet phải kế thừa, thay vì kế thừa trực tiếp từ MonoBehaviour thông thường của Unity. Vai trò của nó hoàn toàn tương đương với NetworkBehaviour đã học ở Fusion (chương 28) — nơi một object chỉ cần gắn kèm NetworkObject + script kế thừa NetworkBehaviour là đã sẵn sàng tham gia networking, không cần khai báo thêm cấu trúc nào khác.

MiddlewareCách gắn networking vào GameObject
FishNetGắn component NetworkObject (đánh dấu object này được framework quản lý vòng đời network) + script kế thừa NetworkBehaviour (chứa logic gameplay có SyncVar/RPC)
Photon FusionTương tự — NetworkObject + script kế thừa NetworkBehaviour (chương 28)
NGONetworkObject + script kế thừa NetworkBehaviour (chương 33) — cấu trúc gần như song song với FishNet, khác chủ yếu ở tên thuộc tính/attribute bên trong

NetworkBehaviour

Ý nghĩa: Class cơ sở cung cấp toàn bộ hạ tầng networking cho một script: khả năng khai báo [SyncVar], gọi các loại RPC (chương 40), tham gia Prediction v2 (chương 41), và một loạt thuộc tính kiểm tra ngữ cảnh runtime cực kỳ hay dùng để rẽ nhánh logic (chỉ chạy đoạn code này nếu đang ở server, chỉ chạy đoạn kia nếu là chủ sở hữu object...).

Thuộc tínhKiểuÝ nghĩa
IsServerboolĐang chạy trên tiến trình có vai trò Server (bao gồm cả trường hợp Host, vì Host = Server + Client cùng lúc).
IsClientboolĐang chạy trên tiến trình có vai trò Client (bao gồm cả Host).
IsOwnerboolTiến trình hiện tại là "chủ sở hữu" (owner) của đúng instance object này — ví dụ nhân vật do chính người chơi đang ngồi trước máy đó điều khiển. Tương đương khái niệm Ownership đã học ở PUN (chương 22) và Input Authority của Fusion (chương 29).
IsHostboolTiến trình vừa là Server vừa là Client cùng lúc (IsServer && IsClient đều đúng) — tương đương khái niệm Host Mode/Listen Server đã quen thuộc từ chương 27 và 32.
IsServerInitializedboolPhiên bản "an toàn thời điểm" của IsServer — chỉ true sau khi phần server của FishNet đã khởi tạo xong hoàn toàn, tránh truy cập sớm trong Awake()/OnEnable() khi networking chưa sẵn sàng.
IsClientInitializedboolTương tự IsServerInitialized nhưng cho phía client.
C# Skeleton toi thieu cua mot NetworkBehaviour
using FishNet.Object;
using UnityEngine;

public class ExampleBehaviour : NetworkBehaviour
{
    public override void OnStartServer()
    {
        base.OnStartServer();
        // Chi chay dung MOT lan tren tien trinh Server, khi object nay
        // duoc "sinh ra"/khoi tao xong phia server
        Debug.Log("Object da san sang tren Server");
    }

    public override void OnStartClient()
    {
        base.OnStartClient();
        // Chay tren MOI client (bao gom ca Host) khi object da duoc dong bo ve
        if (IsOwner)
        {
            Debug.Log("Day la object cua chinh minh");
        }
    }
}

Khi nào dùng: Bất kỳ script nào cần đọc/ghi trạng thái đồng bộ (SyncVar, SyncList), cần gọi RPC, hoặc cần biết ngữ cảnh runtime (đang chạy trên server hay client) đều bắt buộc kế thừa từ NetworkBehaviour thay vì MonoBehaviour trơn.

Lưu ý: Không được tự ý gán giá trị cho một biến đánh dấu [SyncVar] từ phía Client — mặc định, quyền ghi (write permission) của [SyncVar] thuộc về Server; Client cố gán giá trị trực tiếp sẽ không có tác dụng đồng bộ (giá trị cục bộ có thể đổi tạm thời nhưng sẽ bị Server ghi đè lại ở lần đồng bộ kế tiếp) — đúng tinh thần Authoritative Server đã học ở chương 8. Muốn Client yêu cầu thay đổi, cách làm chuẩn là gửi một [ServerRpc] (chương 40) để Server tự thẩm định và ghi lại giá trị.

2. [SyncVar] — đồng bộ tự động một field

[SyncVar] là một attribute đánh dấu lên một field C# thông thường để FishNet tự động theo dõi thay đổi và đồng bộ giá trị mới nhất từ Server xuống mọi Client liên quan, mỗi khi giá trị đổi. Đây là điểm khác biệt cú pháp thú vị nhất so với NGO: NGO yêu cầu bọc giá trị trong một kiểu generic riêng — NetworkVariable<int> health = new NetworkVariable<int>(); — còn FishNet chỉ cần thêm một attribute lên phía trên field int thông thường, giữ nguyên cách viết code gần với "C# thuần" nhất có thể.

MiddlewareCú pháp khai báo dữ liệu đồng bộ 1 giá trị
FishNet[SyncVar] private int health; — field thường, chỉ thêm attribute
Photon Fusion[Networked] public int Health { get; set; } — property đặc biệt, framework can thiệp bằng source generator
NGONetworkVariable<int> health = new(); — kiểu generic bọc riêng, phải truy cập qua .Value

C# [SyncVar]

[SyncVar]
private int health;

[SyncVar(OnChange = nameof(OnHealthChanged))]
private int mana;

private void OnHealthChanged(int oldValue, int newValue, bool asServer)
{
    // Duoc goi tu dong moi khi gia tri thay doi, ca tren Server lan Client
    // asServer = true neu callback nay dang chay o phia Server
}
Tham số tùy chọnÝ nghĩa
OnChangeTên (dạng chuỗi, dùng nameof() để an toàn khi đổi tên refactor) của một hàm callback được framework tự động gọi ngay sau khi giá trị đổi — tương tự OnValueChanged của NetworkVariable (NGO) hay RepNotify của Unreal Engine (sẽ nhắc lại ở chương 44).
ChannelChọn kênh truyền tin cậy (reliable) hay không tin cậy (unreliable) cho riêng field này — mặc định là reliable, phù hợp phần lớn trường hợp (máu, tên người chơi...); có thể đổi sang unreliable cho dữ liệu ít quan trọng nếu cần tiết kiệm băng thông.
WritePermissionAi được phép ghi giá trị — mặc định chỉ Server (ServerOnly), đúng nguyên tắc Authoritative Server; có tùy chọn cho phép Owner ghi trực tiếp trong một số kịch bản đặc biệt (ít dùng, cần cân nhắc kỹ về chống gian lận).

Khi nào dùng: Mọi giá trị đơn lẻ cần đồng bộ trạng thái từ Server ra Client để hiển thị đúng cho tất cả người chơi — máu (Health), điểm số (Score), trạng thái hiện tại (đang choáng, đang tàng hình...). Callback OnChange đặc biệt hữu ích để cập nhật UI (thanh máu, số điểm) đúng thời điểm mà không cần polling (kiểm tra liên tục) giá trị mỗi frame.

3. SyncList<T> / SyncDictionary<K,V> — tập hợp tự động đồng bộ

Với dữ liệu dạng tập hợp — danh sách vật phẩm trong túi đồ, danh sách người chơi trong một team — [SyncVar] đơn thuần không phù hợp (nó chỉ theo dõi được việc gán lại toàn bộ giá trị field, không "nhìn thấy" việc thêm/xóa một phần tử bên trong một List<T> thông thường). FishNet giải quyết bằng hai kiểu tập hợp chuyên dụng: SyncList<T> (tương đương List<T>) và SyncDictionary<K,V> (tương đương Dictionary<K,V>) — cả hai đều tự động phát hiện và đồng bộ chính xác từng thao tác thêm, xóa, sửa phần tử.

C# SyncList<T>

public readonly SyncList<string> items = new SyncList<string>();

// Cac thao tac deu tu dong duoc phat hien va dong bo, KHONG can goi ham dac biet nao them
items.Add("Kiem go");
items.RemoveAt(0);
items[0] = "Khien go";

items.OnChange += OnItemsChanged;

private void OnItemsChanged(SyncListOperation op, int index, string oldItem, string newItem, bool asServer)
{
    // op: Add, RemoveAt, Insert, Set, Clear, Complete...
}

Khi nào dùng: Danh sách vật phẩm nhặt được (inventory), danh sách người chơi trong một team/party, danh sách hiệu ứng (buff/debuff) đang áp dụng lên nhân vật — bất kỳ tập hợp nào cần đồng bộ và cả hai phía (Server ghi, Client hiển thị) cần biết chính xác thao tác nào vừa xảy ra để cập nhật UI hiệu quả (ví dụ chỉ thêm một dòng mới vào danh sách UI thay vì vẽ lại toàn bộ danh sách).

So sánh với Unreal Engine — điểm FishNet được đánh giá tối ưu băng thông: Ở Unreal Engine (sẽ ôn lại kỹ ở chương 44), một TArray hay TMap được đánh dấu Replicated theo cách mặc định sẽ replicate lại toàn bộ mảng mỗi khi có bất kỳ thay đổi nào bên trong nó, trừ khi lập trình viên tự cài đặt kỹ thuật nâng cao Fast Array Serializer (một cơ chế thủ công, khá phức tạp, để chỉ gửi phần thay đổi). Ngược lại, SyncList/SyncDictionary của FishNet có cơ chế theo dõi thay đổi từng phần tử riêng lẻ (per-element delta tracking) ngay từ mặc định, không cần cấu hình gì thêm — chỉ gói và gửi đúng phần tử vừa thay đổi (ví dụ một dòng "thêm 1 item") thay vì gửi lại toàn bộ danh sách. Đây là một trong những lý do cụ thể khiến FishNet được cộng đồng đánh giá tối ưu bộ nhớ/băng thông tốt hơn so với việc replicate tập hợp theo kiểu mặc định của nhiều framework khác.

4. Ví dụ code đầy đủ: PlayerStats

Ví dụ dưới đây ghép cả ba khái niệm vừa học vào một script hoàn chỉnh: một [SyncVar] cho máu kèm callback cập nhật UI, và một SyncList<string> cho danh sách vật phẩm nhặt được, cũng kèm callback cập nhật UI khi danh sách đổi.

C# PlayerStats.cs
using FishNet.Object;
using FishNet.Object.Synchronizing;
using UnityEngine;

public class PlayerStats : NetworkBehaviour
{
    [SyncVar(OnChange = nameof(OnHealthChanged))]
    private int health = 100;

    public readonly SyncList<string> items = new SyncList<string>();

    [SerializeField] private UnityEngine.UI.Text healthText;
    [SerializeField] private Transform itemListUiParent;
    [SerializeField] private GameObject itemUiRowPrefab;

    public override void OnStartClient()
    {
        base.OnStartClient();

        // Dang ky callback ngay khi client nhan duoc object nay
        items.OnChange += OnItemsChanged;

        // Cap nhat UI ngay lan dau bang gia tri hien tai (phong truong hop
        // client vao sau, join giua chung, van thay dung trang thai hien co)
        RefreshHealthUi(health);
    }

    private void OnHealthChanged(int oldValue, int newValue, bool asServer)
    {
        // Chi can cap nhat UI, khong can quan tam toi logic gameplay o day
        RefreshHealthUi(newValue);
    }

    private void RefreshHealthUi(int value)
    {
        if (healthText != null)
            healthText.text = $"HP: {value}/100";
    }

    private void OnItemsChanged(SyncListOperation op, int index, string oldItem, string newItem, bool asServer)
    {
        if (op == SyncListOperation.Add)
        {
            var row = Instantiate(itemUiRowPrefab, itemListUiParent);
            row.GetComponentInChildren<UnityEngine.UI.Text>().text = newItem;
        }
        // Cac truong hop Remove/Clear/Set khac co the xu ly tuong tu tuy nhu cau UI
    }

    // Chi Server moi duoc phep goi ham nay (vi du duoc goi tu ben trong mot
    // [ServerRpc] xu ly nhat vat pham, se hoc chi tiet o chuong 40)
    public void ServerApplyDamage(int amount)
    {
        if (!IsServerInitialized) return;
        health = Mathf.Max(0, health - amount);
    }

    public void ServerAddItem(string itemName)
    {
        if (!IsServerInitialized) return;
        items.Add(itemName);
    }
}

5. Luồng đồng bộ: từ Server tới các Client đang quan sát

Sơ đồ dưới đây minh họa toàn bộ vòng đời của một lần thay đổi [SyncVar]/SyncList, từ lúc Server thay đổi giá trị tới lúc từng Client nhận được và callback OnChange được kích hoạt:

sequenceDiagram participant G as Gameplay logic (Server) participant SV as SyncVar/SyncList (noi bo FishNet) participant C1 as Client A (dang quan sat) participant C2 as Client B (dang quan sat) participant C3 as Client C (khong quan sat object nay) G->>SV: health = health - 10 (server-side) Note over SV: FishNet phat hien gia tri vua doi (dirty) SV->>C1: goi tin dong bo gia tri moi SV->>C2: goi tin dong bo gia tri moi Note over SV,C3: Client C KHONG nhan duoc goi tin nay vi khong quan sat object (Observer System, chi tiet chuong 40) C1->>C1: kich hoat OnHealthChanged(old, new, asServer=false) C2->>C2: kich hoat OnHealthChanged(old, new, asServer=false) Note over G: Tren chinh Server, OnHealthChanged cung duoc goi voi asServer=true
Lưu ý về hiệu năng: Dù SyncList đã tối ưu hơn việc gửi lại toàn bộ mảng, việc thêm/xóa liên tục hàng trăm phần tử trong một frame duy nhất (ví dụ vòng lặp for gọi items.Add() nhiều lần liên tiếp) vẫn tạo ra nhiều gói tin đồng bộ nhỏ lẻ thay vì một gói duy nhất — nếu cần thêm hàng loạt phần tử cùng lúc, nên cân nhắc gom lại thành một cấu trúc dữ liệu duy nhất rồi đồng bộ một lần bằng [SyncVar] (ví dụ một mảng cố định hoặc một chuỗi đã nối sẵn) thay vì lạm dụng thao tác thêm từng phần tử một trong vòng lặp lớn.

Tổng kết chương

NetworkBehaviour là nền tảng bắt buộc cho mọi script networking của FishNet, cung cấp sẵn các thuộc tính ngữ cảnh quen thuộc (IsServer, IsClient, IsOwner, IsHost). [SyncVar] đồng bộ tự động một giá trị đơn với cú pháp gần gũi "C# thuần" hơn hẳn NetworkVariable<T> của NGO, kèm callback OnChange tiện lợi cho việc cập nhật UI. SyncList/SyncDictionary mở rộng cơ chế đó cho dữ liệu tập hợp, với ưu điểm theo dõi thay đổi theo từng phần tử — hiệu quả băng thông hơn hẳn cách replicate toàn bộ mảng mặc định của nhiều framework khác kể cả Unreal Engine. Chương 40 sẽ tiếp nối bằng cơ chế giao tiếp hai chiều còn thiếu: ba loại RPC của FishNet — [ServerRpc], [ObserversRpc], [TargetRpc] — trong đó [ObserversRpc] sẽ giải thích chi tiết khái niệm "Observer" vừa nhắc thoáng qua ở sơ đồ trên.
