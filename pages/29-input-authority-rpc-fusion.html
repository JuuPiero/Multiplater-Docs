PHẦN V · PHOTON FUSION 2

Input Authority & RPC trong Fusion

Chương 28 đã học State Authority — ai quyết định kết quả cuối cùng. Chương này giới thiệu một khái niệm tách biệt nhưng rất dễ nhầm lẫn với nó: Input Authority — ai được phép gửi input cho một object. Đồng thời, chương này trình bày cách gửi RPC (Remote Procedure Call — lời gọi hàm từ xa, đã học khái niệm ở chương 23 với PUN) linh hoạt hơn trong Fusion, cho phép khai báo rõ nguồn và đích ngay trong một attribute duy nhất.

1. Input Authority là gì? Phân biệt với State Authority

Đây là điểm rất dễ gây nhầm lẫn, cần giải thích rõ ràng ngay từ đầu:

  • Input Authority — client có quyền gửi input cho một object cụ thể. Thường (nhưng không phải luôn luôn) là chính người chơi đang điều khiển nhân vật đó.
  • State Authority (đã học chương 28) — bên có quyền quyết định kết quả cuối cùng dựa trên input nhận được.

Trong Host Mode và Client-Server Mode, hai vai trò này thường không trùng nhau: người chơi (Input Authority) gửi input "tôi muốn di chuyển sang trái", nhưng chính Host/Dedicated Server (State Authority) mới là bên thực sự chạy simulation và quyết định nhân vật có thực sự di chuyển sang trái thành công hay không (có thể bị chặn bởi tường, bị hiệu ứng làm chậm, v.v.). Việc tách biệt rạch ròi hai vai trò này là nền tảng để chống gian lận: client chỉ có quyền "đề nghị" thông qua input, không có quyền tự ý quyết định kết quả.

Photon Object.HasInputAuthority

public bool HasInputAuthority { get; }  // thuoc tinh ke thua tu NetworkBehaviour

Ý nghĩa: Kiểm tra xem tiến trình hiện tại có phải là bên được phép gửi input cho NetworkBehaviour này hay không — thường dùng để quyết định "đây có phải máy của chính người chơi đang điều khiển nhân vật này không", ví dụ để bật camera theo dõi, hiển thị UI riêng cho người chơi đó, hoặc chỉ đọc input bàn phím/chuột cục bộ khi HasInputAuthority là true.

2. Thu thập input: OnInput() và INetworkInput

Để gửi input người chơi lên hệ thống Fusion, cần override hàm OnInput() — hàm này được gọi mỗi tick trên client có Input Authority, đọc input local (bàn phím, chuột, cần điều khiển) và đóng gói vào một struct input tùy chỉnh. Đây chính là bước "gửi input lên" đã học lý thuyết ở chương 5 (Client-Side Prediction) — chỉ khác là Fusion cung cấp sẵn cơ chế hạ tầng để thực hiện bước này.

Photon OnInput(NetworkRunner runner, NetworkInput input)

public void OnInput(NetworkRunner runner, NetworkInput input)
{
    // doc input local va dong goi vao struct tuy chinh
}

Ý nghĩa: Callback được NetworkRunner (đã giới thiệu ở chương 26) gọi mỗi tick trên client hiện đang có Input Authority với các object liên quan, để thu thập input local ngay tại thời điểm đó. Bên trong hàm này, lập trình viên đọc trạng thái bàn phím/chuột bằng API Input thông thường của Unity, đóng gói vào một struct implement INetworkInput, rồi gọi input.Set(...) để giao struct đó cho Fusion.

Khi nào dùng: Bắt buộc phải cài đặt ở đúng một nơi (thường trong một script quản lý input tổng, hoặc trực tiếp trong NetworkBehaviour của người chơi) cho mọi dự án Fusion có gameplay cần input từ người chơi.

Photon INetworkInput

public struct PlayerNetworkInput : INetworkInput
{
    public Vector2 MoveDirection;
    public NetworkBool JumpPressed;
}

Ý nghĩa: Interface đánh dấu một struct là "gói input hợp lệ" mà Fusion có thể tự động đóng gói, gửi qua mạng, và lưu vào lịch sử input phục vụ prediction/rewind (chương 30). Nên dùng NetworkBool thay vì bool thường cho các cờ trong struct input để đảm bảo tính tương thích tuyệt đối với cơ chế serialize nội bộ của Fusion.

3. RPC trong Fusion: linh hoạt hơn PUN nhờ khai rõ nguồn và đích

Nhắc lại RPC ở PUN (chương 23): đánh dấu hàm bằng [PunRPC], rồi gọi bằng photonView.RPC("TenHam", target, ...) — target (đích nhận) được chỉ định tại thời điểm gọi. Fusion thay đổi cách tiếp cận: attribute [Rpc(RpcSources.X, RpcTargets.Y)] khai báo ngay tại định nghĩa hàm cả nguồn được phép gọi (RpcSources) lẫn đích nhận được gọi (RpcTargets), giúp kiểm soát chặt chẽ và tường minh hơn ngay từ khi đọc code, không phải lần theo từng lời gọi rải rác trong codebase để biết ai có thể gọi RPC nào.

Photon [Rpc(RpcSources, RpcTargets)]

[Rpc(RpcSources.InputAuthority, RpcTargets.StateAuthority)]
public void RPC_RequestJump()
{
    // chi InputAuthority duoc GOI ham nay,
    // va no chi CHAY tren may la StateAuthority
}
Tham sốGiá trị thường dùngÝ nghĩa
RpcSourcesInputAuthority, StateAuthority, AllAi được phép gọi hàm RPC này — Fusion tự kiểm tra và từ chối lời gọi không hợp lệ, giảm bề mặt tấn công gian lận so với việc phải tự kiểm tra thủ công như PUN
RpcTargetsAll, StateAuthority, InputAuthority, ProxiesHàm sẽ thực sự chạy (thực thi logic bên trong) trên (các) tiến trình nào

Khi nào dùng: Bất kỳ khi nào một bên cần yêu cầu bên kia thực hiện một hành động một lần (không phải dữ liệu liên tục nên dùng [Networked]) — ví dụ client (Input Authority) yêu cầu server (State Authority) xử lý một hành động nhảy, hoặc server thông báo cho tất cả client một sự kiện game (ai đó vừa ghi bàn).

5. Ví dụ đầy đủ: input di chuyển và nhảy

Photon C# — PlayerNetworkInput.cs
using Fusion;
using UnityEngine;

public struct PlayerNetworkInput : INetworkInput
{
    public Vector2 MoveDirection;
    public NetworkBool JumpPressed;
}
Photon C# — PlayerInputCollector.cs (thu thap input tren client co Input Authority)
using Fusion;
using UnityEngine;

public class PlayerInputCollector : NetworkBehaviour, INetworkRunnerCallbacks
{
    public void OnInput(NetworkRunner runner, NetworkInput input)
    {
        var data = new PlayerNetworkInput();

        data.MoveDirection = new Vector2(
            Input.GetAxisRaw("Horizontal"),
            Input.GetAxisRaw("Vertical"));

        data.JumpPressed = Input.GetButton("Jump");

        input.Set(data);
    }

    // Cac callback khac cua INetworkRunnerCallbacks luoc bo de gon vi du
}
Photon C# — PlayerMovement.cs (ap dung input trong FixedUpdateNetwork)
using Fusion;
using UnityEngine;

public class PlayerMovement : NetworkBehaviour
{
    [Networked] public Vector3 Position { get; set; }

    private const float MoveSpeed = 5f;
    private const float JumpForce = 6f;

    public override void FixedUpdateNetwork()
    {
        // GetInput() tra ve input da duoc Fusion dong bo/luu lich su
        // cho chinh tick nay - hoat dong dung cho ca client dang predict
        // lan server dang chay simulation that
        if (GetInput(out PlayerNetworkInput input))
        {
            Vector3 move = new Vector3(input.MoveDirection.x, 0, input.MoveDirection.y);
            Position += move * MoveSpeed * Runner.DeltaTime;

            if (input.JumpPressed)
            {
                RPC_RequestJump();
            }
        }

        transform.position = Position;
    }

    [Rpc(RpcSources.InputAuthority, RpcTargets.StateAuthority)]
    public void RPC_RequestJump()
    {
        // Chi thuc su chay tren may la StateAuthority (Host/Dedicated Server),
        // du InputAuthority (nguoi choi) la ben goi RPC nay
        Debug.Log("Xu ly logic nhay tai StateAuthority");
    }
}
Lưu ý: Không nên tự ý gán trực tiếp Position từ input mà không thông qua kiểm tra hợp lệ ở phía State Authority nếu game cần chống gian lận nghiêm ngặt — ví dụ dưới, phép tính di chuyển trong FixedUpdateNetwork() chạy giống nhau trên cả client dự đoán lẫn server thật, nhưng nếu cần chặn tường/va chạm phức tạp, logic đó cũng phải nằm trong cùng hàm này để đảm bảo tính deterministic (chi tiết ở chương 30).

Tổng kết chương

Input Authority (ai được gửi input) và State Authority (ai quyết định kết quả) là hai khái niệm tách biệt nhưng bổ sung cho nhau trong Fusion — sự tách biệt này chính là nền tảng giúp Fusion chống gian lận tốt hơn PUN. OnInput() cùng INetworkInput là cơ chế chuẩn để thu thập input mỗi tick, còn [Rpc(RpcSources, RpcTargets)] mang lại cách khai báo RPC tường minh và an toàn hơn so với việc chỉ định target lúc gọi như PUN. Chương tiếp theo sẽ giải thích điều làm nên "phép màu" của Fusion: cơ chế Prediction và Reconciliation hoạt động tự động đằng sau FixedUpdateNetwork() và [Networked] property mà ta vừa học.
