PHẦN VI · UNITY NETCODE FOR GAMEOBJECTS

Ví dụ thực hành: NGO + Relay

Chương cuối cùng của Phần VI ghép toàn bộ những gì đã học ở các chương 32–36 thành một luồng chơi hoàn chỉnh: người chơi bấm "Tạo phòng" hoặc "Vào phòng", ứng dụng tự lo phần Relay + Lobby phía sau hậu trường (chương 36), rồi khi kết nối xong, mỗi người chơi được spawn một Player Prefab mang đầy đủ NetworkObject + NetworkTransform (chương 33, 35), có máu đồng bộ bằng NetworkVariable (chương 33), và tấn công lẫn nhau bằng ServerRpc/ClientRpc (chương 34). Kết thúc chương là bảng tổng kết ưu/nhược điểm của NGO so với các giải pháp đã học ở Phần IV và V, chuẩn bị tinh thần trước khi bước sang Phần VII với FishNet.

Cấu trúc scene tối thiểu

Đối tượng trong sceneThành phần cần có
GameObject NetworkManagerNetworkManager + UnityTransport (chương 32) + script GameBootstrap (viết trong chương này) — đối tượng này KHÔNG bị huỷ khi đổi scene (DontDestroyOnLoad, NGO tự xử lý nếu bật đúng tuỳ chọn).
Canvas UIÔ nhập tên phòng + nút "Tạo phòng" (gọi GameBootstrap.OnClickHost), ô nhập mã phòng + nút "Vào phòng" (gọi GameBootstrap.OnClickJoin), một Text hiển thị mã phòng (Lobby Code) sau khi tạo để người chơi khác chép lại.
Player PrefabNetworkObject (chương 33) + NetworkTransform (chương 35) + script PlayerController (viết trong chương này, gộp NetworkVariable<int> Health và các RPC tấn công) — prefab này phải được đăng ký vào danh sách Network Prefabs của NetworkManager (xem lại chương 32) để NGO biết cách khởi tạo đúng khi nhận lệnh spawn.
Các điểm Spawn PointsVài GameObject rỗng đánh dấu vị trí xuất hiện, tránh mọi người chơi spawn chồng lên đúng một điểm.

GameBootstrap.cs — thiết lập Relay + Lobby + StartHost/StartClient

Script dưới đây tổng hợp lại đúng luồng đã trình bày ở chương 36, bổ sung thêm bước spawn Player Prefab thủ công ngay khi một Client kết nối thành công — dùng NetworkObject.SpawnAsPlayerObject() để vừa spawn vừa gán quyền sở hữu (Owner) đúng cho Client vừa vào, thay vì dựa vào cơ chế tự động spawn Player Prefab mặc định của NGO, để có toàn quyền kiểm soát vị trí xuất hiện:

C# GameBootstrap.cs
using System.Collections.Generic;
using System.Threading.Tasks;
using Unity.Services.Authentication;
using Unity.Services.Core;
using Unity.Services.Lobbies;
using Unity.Services.Lobbies.Models;
using Unity.Services.Relay;
using Unity.Services.Relay.Models;
using Unity.Netcode;
using Unity.Netcode.Transports.UTP;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    [SerializeField] private GameObject playerPrefab;
    [SerializeField] private Transform[] spawnPoints;

    Lobby currentLobby;

    async void Awake()
    {
        await UnityServices.InitializeAsync();
        if (!AuthenticationService.Instance.IsSignedIn)
        {
            await AuthenticationService.Instance.SignInAnonymouslyAsync();
        }

        // Dang ky mot lan duy nhat: moi khi co Client moi ket noi thanh cong,
        // ham nay se duoc NGO tu dong goi - nhung than ham chi thuc su lam viec
        // ben phia co tham quyen Server (kiem tra IsServer ngay ben trong)
        NetworkManager.Singleton.OnClientConnectedCallback += HandleClientConnected;
    }

    // Goi tu nut "Tao phong" tren UI
    public async void OnClickHost(string lobbyName, int maxPlayers)
    {
        // maxConnections cua Relay KHONG tinh Host, chi tinh so Client con lai
        Allocation allocation = await RelayService.Instance.CreateAllocationAsync(maxPlayers - 1);
        string relayJoinCode = await RelayService.Instance.GetJoinCodeAsync(allocation.AllocationId);

        var transport = NetworkManager.Singleton.GetComponent<UnityTransport>();
        transport.SetRelayServerData(new RelayServerData(allocation, "dtls"));

        var options = new CreateLobbyOptions
        {
            Data = new Dictionary<string, DataObject>
            {
                { "relayJoinCode", new DataObject(DataObject.VisibilityOptions.Public, relayJoinCode) }
            }
        };
        currentLobby = await LobbyService.Instance.CreateLobbyAsync(lobbyName, maxPlayers, options);
        InvokeRepeating(nameof(SendHeartbeat), 15f, 15f);

        NetworkManager.Singleton.StartHost();
    }

    // Goi tu nut "Vao phong" tren UI, nguoi choi nhap dung Lobby Code
    public async void OnClickJoin(string lobbyCode)
    {
        Lobby joinedLobby = await LobbyService.Instance.JoinLobbyByCodeAsync(lobbyCode);
        string relayJoinCode = joinedLobby.Data["relayJoinCode"].Value;

        JoinAllocation joinAllocation = await RelayService.Instance.JoinAllocationAsync(relayJoinCode);
        var transport = NetworkManager.Singleton.GetComponent<UnityTransport>();
        transport.SetRelayServerData(new RelayServerData(joinAllocation, "dtls"));

        NetworkManager.Singleton.StartClient();
    }

    async void SendHeartbeat()
    {
        if (currentLobby != null)
        {
            await LobbyService.Instance.SendHeartbeatPingAsync(currentLobby.Id);
        }
    }

    // Chi phan than ham nay chay tren may co tham quyen Server (bao gom Host)
    void HandleClientConnected(ulong clientId)
    {
        if (!NetworkManager.Singleton.IsServer) return;

        Transform point = spawnPoints[(int)(clientId % (ulong)spawnPoints.Length)];
        GameObject playerInstance = Instantiate(playerPrefab, point.position, point.rotation);

        // Spawn dong thoi gan quyen so huu (Owner) cho dung Client vua ket noi -
        // tu day IsOwner cua Client do se tra ve true tren chinh object nay
        playerInstance.GetComponent<NetworkObject>().SpawnAsPlayerObject(clientId);
    }
}

PlayerController.cs — gộp NetworkVariable máu và tấn công bằng RPC

Script gắn trên Player Prefab, tái sử dụng đúng khuôn mẫu đã học ở chương 33 (NetworkVariable<int> với quyền ghi mặc định Server) và chương 34 (ServerRpc/ClientRpc cho hành động tấn công). Việc di chuyển vị trí và hiệu ứng animation không cần viết thêm dòng code nào — đã có sẵn NetworkTransform/NetworkAnimator gắn kèm trên cùng prefab (chương 35), tự động đồng bộ song song mà không xung đột với script này:

C# PlayerController.cs
using UnityEngine;
using Unity.Netcode;

// Prefab nay da co san NetworkTransform va (tuy chon) NetworkAnimator gan kem -
// hai component do tu lo phan dong bo vi tri/animation, khong can dong cham o day
[RequireComponent(typeof(NetworkObject))]
public class PlayerController : NetworkBehaviour
{
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private float attackRange = 2f;
    [SerializeField] private int damage = 20;

    public NetworkVariable<int> Health = new NetworkVariable<int>(
        value: 100,
        writePerm: NetworkVariableWritePermission.Server
    );

    public override void OnNetworkSpawn()
    {
        Health.OnValueChanged += HandleHealthChanged;
    }

    public override void OnNetworkDespawn()
    {
        Health.OnValueChanged -= HandleHealthChanged;
    }

    void Update()
    {
        // Chi Owner moi doc input va tu di chuyen object cua chinh minh -
        // NetworkTransform (mac dinh Server Authoritative) se tu dong bo lai
        // vi tri nay cho moi may khac sau khi Server xac nhan
        if (!IsOwner) return;

        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");
        transform.Translate(new Vector3(h, 0, v) * moveSpeed * Time.deltaTime);

        if (Input.GetKeyDown(KeyCode.Space))
        {
            AttackServerRpc();
        }
    }

    [ServerRpc]
    void AttackServerRpc(ServerRpcParams rpcParams = default)
    {
        Collider[] hits = Physics.OverlapSphere(transform.position, attackRange);
        foreach (var hit in hits)
        {
            PlayerController target = hit.GetComponent<PlayerController>();
            if (target != null && target != this)
            {
                target.TakeDamage(damage);
            }
        }

        PlayAttackEffectClientRpc();
    }

    // Chi Server duoc goi ham nay (kiem tra IsServer o day thay vi ServerRpc
    // vi ham nay duoc goi truc tiep tu code Server, khong phai tu Client)
    public void TakeDamage(int amount)
    {
        if (!IsServer) return;

        Health.Value = Mathf.Max(0, Health.Value - amount);
    }

    [ClientRpc]
    void PlayAttackEffectClientRpc()
    {
        // Chay tren MOI client - vi du phat animation vung vu khi, am thanh
        Debug.Log($"{name} vua tung mot don tan cong");
    }

    void HandleHealthChanged(int oldValue, int newValue)
    {
        // Cap nhat thanh mau UI ngay lap tuc tren MOI may, khong can polling
        if (newValue == 0)
        {
            Debug.Log($"{name} da bi ha guc");
        }
    }
}

Đọc sơ đồ: Đây chính là bức tranh tổng thể của toàn bộ Phần VI: Relay/Lobby (chương 36) chỉ tham gia ở giai đoạn thiết lập kết nối ban đầu; ngay khi StartHost()/StartClient() hoàn tất, mọi thứ còn lại (spawn, đồng bộ Transform, đồng bộ biến, RPC) đều do NGO tự vận hành qua đúng những cơ chế đã học ở chương 33–35, không còn liên quan gì tới Relay/Lobby nữa — hai dịch vụ đó chỉ đóng vai trò "bắc cầu" ban đầu.

Ưu điểm & nhược điểm của NGO

Chi tiết
Ưu điểm Miễn phí, không giới hạn CCU (Concurrent Users — số người chơi kết nối đồng thời): khác với PUN free tier vốn giới hạn số CCU tối đa trước khi phải trả phí (chương 20), tự host qua Relay của NGO không bị áp mức trần CCU cứng nào từ phía framework networking (chi phí thực tế nếu có chỉ tới từ hạn mức sử dụng của riêng dịch vụ Relay/Lobby, không phải từ bản thân NGO).
Tích hợp chính thức của Unity: NGO nằm trong hệ sinh thái Unity Gaming Services chính chủ, được cập nhật song song với các phiên bản Unity Editor mới, tương thích sẵn với các dịch vụ khác (Authentication, Lobby, Relay, Vivox thoại...).
Mã nguồn mở: toàn bộ package NGO công khai trên GitHub, lập trình viên có thể tự đọc, debug sâu, thậm chí sửa trực tiếp khi cần hiểu rõ hành vi nội bộ — điều PUN/Fusion (mã nguồn đóng, chỉ có DLL biên dịch sẵn) không cho phép.
Nhược điểm Hệ sinh thái/tài liệu cộng đồng còn trẻ hơn Photon: Photon (PUN, Fusion) đã tồn tại lâu năm hơn, có lượng lớn tutorial, plugin bên thứ ba, và kinh nghiệm sản xuất (production) tích luỹ từ cộng đồng rộng hơn.
Thiếu Prediction/Rollback built-in mạnh như Fusion: Photon Fusion (chương 30) có sẵn cơ chế tick-based simulation, prediction và reconciliation tích hợp sâu ngay trong lõi framework; NGO không có sẵn tầng prediction tương đương mức độ đó — muốn có client-side prediction mượt cho game hành động nhanh, lập trình viên thường phải tự xây dựng thêm logic dự đoán/hiệu chỉnh riêng trên nền RPC và NetworkVariable đã học.

Tổng kết Phần VI

Phần VI đã đi trọn vòng đời của một dự án multiplayer dùng NGO: từ NetworkManager khởi tạo kết nối (chương 32), NetworkObject/NetworkVariable làm nền tảng đồng bộ trạng thái (chương 33), ServerRpc/ClientRpc xử lý hành động và sự kiện tức thời (chương 34), NetworkTransform/NetworkAnimator đồng bộ chuyển động không cần viết code (chương 35), cho tới Unity Relay/Lobby giải quyết bài toán kết nối và tìm phòng qua Internet (chương 36) — và ví dụ thực hành này ghép tất cả lại thành một luồng chơi thật sự chạy được. Phần VII tiếp theo sẽ giới thiệu FishNet — một framework networking mã nguồn mở khác của cộng đồng, thường được so sánh trực tiếp với cả Mirror lẫn NGO, mang thêm một góc nhìn thiết kế API và một hệ thống Prediction v2 (rollback netcode) đáng chú ý.
