PHẦN VI · UNITY NETCODE FOR GAMEOBJECTS

NetworkObject & NetworkVariable

Chương 32 đã giới thiệu NetworkManager — bộ não trung tâm quản lý kết nối và chọn Transport, nhưng bản thân nó không đồng bộ bất kỳ dữ liệu gameplay nào. Chương này đi vào hai khối xây dựng gắn trực tiếp lên từng GameObject cần tham gia mạng: NetworkObject — "giấy thông hành" bắt buộc để một object được NGO nhận diện và đồng bộ, và NetworkVariable<T> — cơ chế đồng bộ dữ liệu tự động, tương đương vai trò của [Networked] ở Photon Fusion (chương 28) hay việc tự viết OnPhotonSerializeView ở PUN (chương 23) nhưng với cách tiếp cận generic, khai báo tường minh riêng của NGO.

NetworkObject — giấy thông hành bắt buộc

C# NetworkObject

Ý nghĩa: NetworkObject là component bắt buộc phải gắn lên bất kỳ GameObject nào cần tham gia networking — đóng vai trò tương đương PhotonView đã học ở PUN (chương 22) hoặc chính NetworkObject/NetworkBehaviour của Fusion (chương 28). Không có component này, GameObject chỉ tồn tại cục bộ trên đúng một máy, không được bất kỳ máy nào khác biết tới.

Thuộc tínhÝ nghĩa
NetworkObjectIdSố định danh (ulong) duy nhất trong toàn phiên chơi, được Server cấp phát tại thời điểm spawn — dùng để mọi client biết chính xác gói tin cập nhật nào ứng với object nào, mà không cần gửi lại toàn bộ thông tin object qua mạng mỗi lần.

C# Spawn() / Despawn()

void NetworkObject.Spawn(bool destroyWithScene = false);
void NetworkObject.Despawn(bool destroy = true);

Ý nghĩa: Spawn() đăng ký một NetworkObject đã Instantiate() cục bộ (dùng GameObject.Instantiate() tiêu chuẩn của Unity trên prefab có sẵn trong danh sách NetworkPrefabs, chương 32) vào hệ thống networking, khiến nó xuất hiện đồng bộ trên mọi client đang kết nối. Despawn() làm ngược lại — gỡ object khỏi hệ thống đồng bộ và (mặc định) hủy nó trên mọi máy.

Khác biệt CƠ BẢN với PUN — đọc kỹ trước khi viết code: NetworkObject.Spawn() chỉ được phép gọi từ phía Server (bao gồm Host, vì Host cũng đóng vai trò Server). Gọi hàm này từ một client thường sẽ ném lỗi ngay lập tức, không có ngoại lệ. Đây là khác biệt nền tảng so với PhotonNetwork.Instantiate() của PUN (chương 22) — vốn cho phép bất kỳ client thường nào cũng tự spawn object của riêng mình lên Photon Cloud. Sự khác biệt này phản ánh đúng triết lý Authoritative Server nghiêm ngặt hơn của NGO: mọi quyết định "vật gì được tạo ra, khi nào" đều phải đi qua Server có thẩm quyền, không client nào được tự ý bơm object mới vào thế giới game — hạn chế đáng kể một lớp gian lận phổ biến (spawn vật phẩm giả, spawn quân địch giả) mà kiến trúc relay của PUN vốn dễ bị lợi dụng hơn (liên hệ lại bài học chống gian lận ở chương 8).

Đây chính là điểm then chốt khiến kiến trúc NGO khó bị gian lận spawn hơn PUN.

Ngữ cảnh vai trò trên NetworkBehaviour: IsOwner, IsServer, IsClient, IsHost

Mọi script gắn logic networking trong NGO đều kế thừa từ NetworkBehaviour (thay vì MonoBehaviour thường) — lớp cơ sở này tự động phơi ra bốn thuộc tính boolean kiểm tra ngữ cảnh đang chạy trên chính object đó:

Thuộc tính (NGO)Ý nghĩaTương đương ở Fusion (chương 28–29)Tương đương ở PUN (chương 22)
IsOwnertrue nếu tiến trình hiện tại là chủ sở hữu (owner) của NetworkObject nàyHasInputAuthority (gần đúng, có sắc thái khác — Fusion tách bạch Input Authority/State Authority)photonView.IsMine
IsServertrue nếu tiến trình hiện tại có vai trò Server (bao gồm Host)HasStateAuthority (trong Server Mode, đồng nhất với Server)Không có khái niệm tương đương trực tiếp — PUN không có Server thật (chương 20)
IsClienttrue nếu tiến trình hiện tại có vai trò Client (bao gồm Host)Luôn true (mọi peer Fusion đều là client theo nghĩa nào đó)Luôn true
IsHosttrue chỉ khi vừa Server vừa Client cùng lúcĐồng nghĩa GameMode.HostKhông có khái niệm tương đương (mọi client PUN ngang hàng, chỉ khác vai trò Master Client)

Điểm cần khắc sâu: NGO tách rõ ràng nhiều cờ hơn so với PUN (vốn chỉ có một cờ IsMine duy nhất) để kiểm tra chính xác vai trò trong từng tình huống — ví dụ một đoạn code chỉ nên chạy logic gameplay có thẩm quyền khi IsServer == true, nhưng chỉ nên cập nhật hiệu ứng hình ảnh cục bộ khi IsOwner == true; nhầm lẫn giữa hai cờ này là lỗi rất phổ biến khi mới học NGO.

NetworkVariable<T> — đồng bộ dữ liệu tự động

C# NetworkVariable<T>

public class NetworkVariable<T> : NetworkVariableBase
{
    public T Value { get; set; }
    public event System.Action<T, T> OnValueChanged; // (gia tri cu, gia tri moi)
}

Ý nghĩa: NetworkVariable<T> là một kiểu dữ liệu generic đặc biệt bọc quanh một giá trị bất kỳ để tự động đồng bộ giá trị đó qua mạng mỗi khi nó thay đổi — lập trình viên không cần tự viết code serialize/gửi gói tin thủ công như khi tự chế giao thức nhị phân ở chương 10. Dùng được với hầu hết kiểu dữ liệu cơ bản (int, float, bool, Vector3...) và cả struct tùy chỉnh, miễn là struct đó hiện thực đúng interface serialize mà NGO yêu cầu (INetworkSerializable, hoặc struct chỉ gồm toàn kiểu unmanaged cơ bản để NGO tự serialize được).

Khai báo và sử dụng: đọc/ghi giá trị luôn thông qua thuộc tính .Value, không thao tác trực tiếp lên biến như một field thường:

C# Khai báo và đọc/ghi NetworkVariable
public class PlayerHealth : NetworkBehaviour
{
    // Khoi tao gia tri mac dinh la 100 ngay khi object duoc tao
    public NetworkVariable<int> Health = new NetworkVariable<int>(100);

    void SomeMethod()
    {
        int current = Health.Value;   // doc gia tri hien tai
        Health.Value = current - 10;  // ghi gia tri moi - tu dong dong bo neu co quyen
    }
}

C# OnValueChanged — lắng nghe thay đổi thay vì polling

Ý nghĩa: Mỗi NetworkVariable<T> có sẵn sự kiện OnValueChanged, được gọi tự động ngay khi giá trị thay đổi (cả trên máy ghi lẫn trên mọi máy nhận được bản cập nhật) — tham số truyền vào là cặp (giá trị cũ, giá trị mới). Đây là cơ chế cực kỳ hữu ích để cập nhật UI hay hiệu ứng ngay khi dữ liệu đổi, thay vì phải Update() kiểm tra giá trị mỗi frame (polling) như lập trình viên mới thường làm.

Liên hệ kiến thức đã học: Cơ chế này tương tự RepNotify của Unreal Engine (khai báo UPROPERTY(ReplicatedUsing = OnRep_Health), gọi hàm OnRep_Health() tự động khi giá trị Replicate đổi — đã học ở bộ tài liệu Unreal riêng, chương "Replication & RepNotify") — cùng một ý tưởng "callback khi dữ liệu đồng bộ thay đổi", chỉ khác cú pháp: NGO dùng event C# tiêu chuẩn, Unreal dùng UFUNCTION được đặt tên theo quy ước OnRep_<TenBien>.

C# NetworkVariableWritePermission

public enum NetworkVariableWritePermission { Server, Owner }

new NetworkVariable<int>(
    value: 100,
    writePerm: NetworkVariableWritePermission.Server
);

Ý nghĩa: Tham số cấu hình ai được phép ghi giá trị mới vào NetworkVariable — đọc thì mọi máy (Server lẫn mọi Client) đều luôn đọc được tự do, chỉ khác nhau ở quyền ghi:

Giá trịÝ nghĩaKhi nào dùng
Server (mặc định)Chỉ Server mới được gán .Value mới; Client cố ghi sẽ bị từ chối/ném lỗiMọi dữ liệu nhạy cảm, cần chống gian lận — máu, điểm số, tiền tệ trong game — đúng chuẩn Authoritative Server đã học ở chương 8
OwnerChủ sở hữu (owner) của NetworkObject đó cũng được ghi trực tiếp, không cần đi qua ServerRpcDữ liệu không nhạy cảm bảo mật, ít quan trọng nếu bị can thiệp — ví dụ màu áo tùy chỉnh, tên hiển thị, trạng thái UI cục bộ không ảnh hưởng luật chơi
Lưu ý: Chọn Owner cho dữ liệu ảnh hưởng trực tiếp tới kết quả trận đấu (máu, sát thương, tiền thưởng) là một lỗ hổng bảo mật kinh điển — client đó hoàn toàn có thể sửa giá trị cục bộ để gian lận (ví dụ tự đặt máu về vô hạn) và giá trị gian lận đó sẽ được coi là "hợp lệ" rồi tự động lan ra mọi máy khác. Luôn ưu tiên Server cho bất kỳ dữ liệu nào ảnh hưởng luật chơi, chỉ dùng Owner khi đã cân nhắc kỹ hậu quả bảo mật.

C# Struct tùy chỉnh với INetworkSerializable

Ý nghĩa: Với kiểu dữ liệu cơ bản (int, float, bool, Vector3, Quaternion...), NGO tự biết cách serialize mà không cần khai báo gì thêm. Với một struct tự định nghĩa (ví dụ gộp nhiều trường trạng thái vào một biến duy nhất để tiết kiệm số lượng NetworkVariable phải khai báo), struct đó phải hiện thực interface INetworkSerializable để NGO biết cách chuyển đổi nó qua lại giữa dạng object trong bộ nhớ và dạng byte gửi qua mạng — về bản chất là một hình thức serialize thủ công tương tự tinh thần đã học ở chương 10, nhưng đóng khung gọn trong một interface chuẩn của NGO.

C# PlayerStats.cs — struct tuỳ chỉnh dùng được trong NetworkVariable
using Unity.Netcode;

public struct PlayerStats : INetworkSerializable
{
    public int Level;
    public int Experience;

    public void NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter
    {
        // Ca hai chieu doc (deserialize) va ghi (serialize) deu goi chung mot ham nay,
        // BufferSerializer<T> tu quyet dinh dang doc hay ghi tuy ngu canh goi
        serializer.SerializeValue(ref Level);
        serializer.SerializeValue(ref Experience);
    }
}

public class PlayerProgress : NetworkBehaviour
{
    public NetworkVariable<PlayerStats> Stats =
        new NetworkVariable<PlayerStats>(new PlayerStats { Level = 1, Experience = 0 });
}
Lưu ý — giới hạn của NetworkVariable với danh sách/mảng: NetworkVariable<T> phù hợp cho một giá trị đơn (một số, một struct nhỏ), không phải giải pháp tối ưu để đồng bộ một danh sách có kích thước thay đổi liên tục — mỗi lần chỉ thêm/bớt một phần tử, toàn bộ nội dung vẫn phải gửi lại nguyên khối nếu dùng trực tiếp NetworkVariable<List<T>>. NGO cung cấp riêng NetworkList<T> cho đúng nhu cầu này (theo dõi từng thao tác Add/Remove/thay đổi phần tử và chỉ gửi phần thay đổi, hiệu quả hơn hẳn) — ngoài phạm vi chi tiết của chương này nhưng đáng biết tên khi cần đồng bộ một danh sách (ví dụ danh sách vật phẩm trong túi đồ).

Ví dụ đầy đủ: PlayerHealth với NetworkVariable

Ví dụ dưới đây ghép toàn bộ các khái niệm của chương: NetworkBehaviour, NetworkVariable<int> với quyền ghi mặc định Server, kiểm tra IsServer trước khi thay đổi giá trị, và OnValueChanged để tự động cập nhật UI trên mọi client mà không cần polling:

C# PlayerHealth.cs
using UnityEngine;
using Unity.Netcode;

public class PlayerHealth : NetworkBehaviour
{
    // Mac dinh WritePermission = Server: chi Server duoc ghi, moi client chi doc
    public NetworkVariable<int> Health = new NetworkVariable<int>(
        value: 100,
        writePerm: NetworkVariableWritePermission.Server
    );

    public override void OnNetworkSpawn()
    {
        // Dang ky lang nghe thay doi ngay khi object duoc spawn xong
        Health.OnValueChanged += HandleHealthChanged;
    }

    public override void OnNetworkDespawn()
    {
        // Luon huy dang ky de tranh memory leak khi object bi despawn
        Health.OnValueChanged -= HandleHealthChanged;
    }

    // Chi Server moi duoc phep thuc su goi ham nay va thay doi gia tri
    public void TakeDamage(int amount)
    {
        if (!IsServer)
        {
            Debug.LogWarning("TakeDamage() chi duoc goi tren Server!");
            return;
        }

        Health.Value = Mathf.Max(0, Health.Value - amount);

        if (Health.Value == 0)
        {
            Debug.Log("Player da bi ha guc, xu ly logic respawn o day");
        }
    }

    // Callback nay chay tren MOI may (Server lan tat ca Client) moi khi gia tri doi
    void HandleHealthChanged(int oldValue, int newValue)
    {
        Debug.Log($"Health thay doi: {oldValue} -> {newValue}");
        // Vi du cap nhat thanh mau UI ngay lap tuc, khong can Update() moi frame
        // healthBarUI.SetValue(newValue);
    }
}

Tổng kết chương

NetworkObject là điều kiện bắt buộc để một GameObject tồn tại trong thế giới nhiều người chơi, với hai định danh quan trọng (NetworkObjectId để phân biệt từng instance, GlobalObjectIdHash để biết đúng prefab cần khởi tạo) và quy tắc chỉ Server được Spawn/Despawn — khác biệt an toàn hơn hẳn so với việc PUN cho phép client tự Instantiate(). NetworkVariable<T> giải quyết bài toán đồng bộ dữ liệu declarative, có cấu hình quyền ghi rõ ràng (Server hay Owner) và sự kiện OnValueChanged để phản ứng tức thời. Nhưng NetworkVariable chỉ giải quyết được bài toán "đồng bộ trạng thái" — chương 34 sẽ bổ sung mảnh ghép còn thiếu: làm sao để client yêu cầu Server thực hiện một hành động (bắn súng, mở cửa...) và làm sao Server thông báo ngược lại cho mọi client về một sự kiện đã xảy ra, thông qua ServerRpc và ClientRpc.
