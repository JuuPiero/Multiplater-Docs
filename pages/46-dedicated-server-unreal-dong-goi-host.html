PHẦN VIII · UNREAL ENGINE NETWORKING

Dedicated Server Unreal: Đóng gói & Host

Chương 43 đã nhắc tới Dedicated Server như một trong ba chế độ chạy một project Unreal (cùng Standalone và Listen Server), và chương 45 vừa xác nhận: nếu dự án dùng Unreal, hầu như không cần middleware bên thứ ba nào để có được một máy chủ chạy logic gameplay thật. Chương này đi tiếp bước tiếp theo trong vòng đời một Dedicated Server thật: đóng gói nó thành một chương trình chạy được, và host nó ở đâu để người chơi thật kết nối tới. Trọng tâm không phải dạy lại chi tiết Unreal Build Tool (đã có bộ tài liệu Unreal C++ riêng), mà đối chiếu trực tiếp việc host một Dedicated Server Unreal với việc host (hoặc không cần host) cho từng middleware Unity đã học ở Phần IV–VII — vì đây chính là điểm khác biệt vận hành thực tế lớn nhất giữa các lựa chọn.

Recap ngắn: Dedicated Server Build là gì

Một dự án Unreal có thể được biên dịch (build) thành nhiều loại Target khác nhau, khai báo trong file *.Target.cs của project — quyết định loại chương trình cuối cùng tạo ra. Loại quan trọng nhất cho chương này là TargetType.Server:

Unreal C++ MyGameServer.Target.cs — khai bao Target Type = Server
using UnrealBuildTool;
using System.Collections.Generic;

public class MyGameServerTarget : TargetRules
{
    public MyGameServerTarget(TargetInfo Target) : base(Target)
    {
        Type = TargetType.Server;   // BUOC QUYET DINH: bien dich ra Dedicated Server
        DefaultBuildSettings = BuildSettingsVersion.Latest;
        ExtraModuleNames.AddRange(new string[] { "MyGame" });
    }
}

Khi Type = TargetType.Server, Unreal Build Tool tạo ra một executable headless — không đồ hoạ, không cần GPU, không khởi tạo bất kỳ thành phần rendering/âm thanh/input thiết bị nào — chỉ chạy thuần logic gameplay (Actor, Tick, GameMode) và xử lý mạng (Replication, RPC). Trên Windows, tên file thường có hậu tố Server.exe; trên Linux, không có phần mở rộng, chỉ là một binary ELF thuần túy chạy được ngay trên một máy chủ Linux/Windows server không cần màn hình.

Đọc sâu hơn: Cấu trúc đầy đủ của file Target.cs, sự khác biệt giữa TargetType.Game/Client/Server/Editor, cùng toàn bộ quy trình hoạt động của Unreal Build Tool (UBT) và Unreal Header Tool (UHT) được trình bày đầy đủ trong bộ tài liệu Unreal Engine C++ riêng, chương về Unreal Build Tool & Header Tool — chương này chỉ nhắc lại đúng phần liên quan trực tiếp tới việc đóng gói và host một máy chủ multiplayer.

So sánh: host cho Unreal Dedicated Server vs host cho middleware Unity

Đây là bảng trung tâm của chương: cùng đặt câu hỏi "ai phải tự dựng và duy trì một tiến trình server chạy 24/7" cho cả năm hệ thống đã học xuyên suốt tài liệu.

Hệ thốngCó cần tự host tiến trình server khôngGhi chú
Unreal Dedicated ServerCó — bắt buộcTự đóng gói executable headless (như trên), tự chọn nơi chạy (máy chủ riêng, cloud, container)
PUNKhôngPhoton Cloud (chương 20) lo toàn bộ hạ tầng relay — không có khái niệm "server chạy logic" để tự host
Fusion — Client-Server ModeCó — bắt buộcCần tự host một tiến trình server riêng (chương 27), tương tự hoàn toàn Unreal Dedicated Server về mặt vận hành
NGO + Unity RelayKhông bắt buộc, nhưng có đánh đổiRelay (chương 36) giúp không cần tự host, nhưng khi đó logic game chạy trên máy của một Client đóng vai trò Host — chỉ có host thật (self-hosted Dedicated Server riêng) mới tránh được việc "Host cũng là một người chơi"
FishNetTương tự NGOCó thể chạy kiểu Host (một Client kiêm Server) hoặc tự host Dedicated Server riêng nếu muốn tách bạch hoàn toàn
Điểm dễ hiểu nhầm về NGO/FishNet + Relay: "Không cần tự host" ở đây chỉ đúng cho phần hạ tầng chuyển tiếp gói tin (Relay giúp hai máy sau NAT nói chuyện được với nhau, giống tinh thần Photon Cloud) — không có nghĩa là có một máy chủ trung lập chạy logic gameplay. Theo mặc định, logic game (GameManager, Server-authoritative checks) vẫn chạy trên máy của một Client được chỉ định làm Host — máy đó vừa chơi vừa gánh vai trò Server, y hệt khái niệm Listen Server của Unreal (chương 43). Muốn có một tiến trình Server thật sự tách biệt, trung lập, không phải máy của người chơi nào, dự án NGO/FishNet vẫn phải tự deploy một Dedicated Server build riêng — lúc đó bài toán vận hành mới thực sự giống Unreal Dedicated Server.

Quy trình thực tế: deploy Dedicated Server Unreal lên cloud

Sau khi có executable headless từ Target Type Server, quy trình phổ biến hiện nay để đưa nó lên hạ tầng thật gồm ba bước lớn:

  1. Đóng gói container Docker: executable Dedicated Server (thường build cho Linux, vì hầu hết hạ tầng cloud chạy Linux với chi phí thấp hơn Windows Server) cùng toàn bộ file dữ liệu game cần thiết (Pak file, Content đã cook) được đóng gói vào một Docker image — một "gói" độc lập chứa mọi thứ cần để chạy, không phụ thuộc vào cấu hình máy chủ vật lý bên dưới.
  2. Triển khai qua Kubernetes: Kubernetes (thường viết tắt K8s) là hệ thống điều phối container phổ biến, tự động quyết định chạy bao nhiêu instance của Docker image đó, trên máy vật lý/ảo nào, tự khởi động lại nếu một tiến trình Server bị crash, và tự mở rộng số lượng khi có nhiều trận đấu cần khởi tạo cùng lúc.
  3. Hoặc dùng dịch vụ chuyên biệt cho game server hosting: thay vì tự quản lý Kubernetes, nhiều dự án chọn một dịch vụ đã chuyên biệt hóa cho đúng bài toán "chạy hàng loạt phiên Dedicated Server game" (ví dụ Amazon GameLift đã nhắc ở chương 45) — dịch vụ này hiểu sẵn khái niệm "một phiên chơi = một tiến trình server", tự động điều phối người chơi vào đúng tiến trình còn chỗ, và xử lý phần auto-scaling mà không cần tự cấu hình Kubernetes từ đầu. Chi tiết đầy đủ về các lựa chọn hosting/scaling nằm ở chương 50.
Dockerfile Vi du toi gian dong goi Dedicated Server Unreal (Linux)
# Image nen toi gian, chi can thu vien he thong ma binary Unreal doi hoi,
# KHONG can driver do hoa/GPU vi day la build headless
FROM ubuntu:22.04

# Sao chep toan bo thu muc build Dedicated Server da dong goi tu Unreal
# (thuong nam trong LinuxServer/ sau khi chay quy trinh Package Project voi Target = Server)
COPY LinuxServer/ /game/

WORKDIR /game
# Mo cong UDP ma Unreal dung cho gameplay traffic (mac dinh 7777, co the doi qua config)
EXPOSE 7777/udp

# Chay truc tiep executable headless, khong can Xvfb hay man hinh ao
CMD ["/game/MyGameServer.sh", "-log"]
Build Configuration — Development vs Shipping: Khi đóng gói Dedicated Server để đưa lên production, nên dùng cấu hình Shipping (đã tối ưu, không kèm công cụ debug, kích thước nhỏ hơn) thay vì Development (giữ log chi tiết và một số công cụ hỗ trợ debug, phù hợp môi trường kiểm thử nội bộ hoặc CI trước khi phát hành chính thức). Việc chọn sai cấu hình — ví dụ vô tình đưa build Development lên phục vụ hàng nghìn người chơi thật — có thể gây lãng phí tài nguyên CPU/RAM đáng kể do các phép kiểm tra debug bổ sung vẫn được thực thi ở mỗi tick, dù không ai đang xem log đó.

Chi phí vận hành — khác biệt lớn nhất cần nhớ

Đây là hệ quả thực tế quan trọng nhất của việc "cần tự host": chi phí vận hành không còn tính theo số người chơi thực tế đang online tại một thời điểm, mà tính theo số tiến trình server đang chạy, bất kể có người chơi hay không.

Mô hìnhCách tính chi phíĐặc điểm
Unreal Dedicated Server / Fusion Client-Server ModeChi phí server liên tục — trả tiền cho hạ tầng (CPU/RAM/băng thông của máy chủ) suốt thời gian tiến trình còn chạyĐòi hỏi lập kế hoạch chi phí vận hành xuyên suốt toàn bộ vòng đời game, kể cả giai đoạn ít người chơi — phải tự cân đối giữa việc giữ đủ server sẵn sàng (tránh người chơi phải chờ) và không lãng phí (chạy dư thừa server không ai dùng)
PUN / NGO+Relay (không tự host)Trả phí theo CCU sử dụng thực tế (Concurrent Users — số kết nối đồng thời)Không tốn chi phí khi không có người chơi online; chi phí tăng/giảm tự động theo lưu lượng thực tế, không cần tự lo bài toán auto-scaling hạ tầng
Hệ quả cho việc lập kế hoạch dự án: Một studio chọn Unreal Dedicated Server (hoặc Fusion Client-Server Mode) cần dự trù ngân sách vận hành máy chủ như một khoản chi phí cố định hàng tháng kéo dài suốt thời gian game còn được vận hành — kể cả sau khi đã ra mắt và lượng người chơi giảm dần theo thời gian, khác hẳn tư duy "trả tiền theo mức dùng" của các mô hình dựa trên Relay/Cloud không tự host. Đây là một yếu tố kinh doanh cần cân nhắc song song với yếu tố kỹ thuật khi chọn kiến trúc networking cho một dự án dài hạn, không chỉ đơn thuần là câu hỏi "công nghệ nào tốt hơn".

Kết luận chương

Ba điều mang theo sang chương 47: (1) Dedicated Server Unreal là một executable headless được tạo ra bằng cách khai báo TargetType.Server trong Target.cs, không cần đồ hoạ hay GPU; (2) về mặt vận hành, nó giống hệt việc tự host Fusion Client-Server Mode hơn là giống PUN hay NGO+Relay (vốn không bắt buộc tự host) — quy trình thực tế phổ biến là đóng gói Docker, triển khai qua Kubernetes hoặc dịch vụ game server hosting chuyên biệt; (3) chi phí vận hành của mô hình tự host là chi phí liên tục theo thời gian, khác biệt căn bản với chi phí theo CCU của các mô hình không tự host. Chương 47 sẽ đưa toàn bộ lý thuyết của Phần VIII vào một ví dụ code cụ thể: cùng một bài toán đồng bộ vị trí nhân vật, viết song song theo cả hai cách — Unreal thuần và qua Photon PUN.
